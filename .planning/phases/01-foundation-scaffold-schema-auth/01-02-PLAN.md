# Plan 01-02: Auth API, RBAC, and Client Session Flows

## Objective

Deliver end-to-end authentication and role-based access for Salão Linda: secure credential handling, JWT session lifecycle, server-enforced authorization, and Vue/Pinia flows so users can register, login, stay signed in, logout, and admins can recover client access via password reset.

## Context

- Depends on Plan 01-01 (scaffold, env, DB, migrations, admin bootstrap).
- Read: `.planning/phases/01-foundation-scaffold-schema-auth/01-RESEARCH.md`
- Requirements mapping: AUTH-01 register/login (client), AUTH-02 admin login + gestão access, AUTH-03 logout + session persistence, AUTH-04 admin resets client password.
- Security baseline: bcryptjs cost 12, JWT verify with pinned algorithm (HS256), role hardcoded/validated server-side, rate-limit auth endpoints, never trust client role.

<task id="1" type="backend-auth">
<title>Implement auth services, tokens, and middleware</title>
<files>
- `api/src/db/*` (knex/pool instance)
- `api/src/services/authService.*` (or equivalent)
- `api/src/middleware/authenticate.*`
- `api/src/middleware/requireAdmin.*`
- `api/src/validators/authSchemas.*`
- `api/src/utils/password.*`, `api/src/utils/jwt.*`
- `api/src/routes/auth.routes.*`
- `api/src/routes/admin.routes.*`
- `api/src/app.*` / `api/src/server.*` (wire middleware/routes)
</files>
<action>
1. Implement DB access helpers for users and refresh_tokens (find by phone/id, create user, update password hash, store/find/revoke refresh token records). Store refresh tokens safely (hashed token or jti-based lookup) with expiry/revocation.
2. Implement auth logic:
   - Register: validate input (zod), normalize phone, reject duplicates, hash password (bcryptjs), insert user with `role='client'` forced, issue access+refresh tokens.
   - Login: validate, fetch user, compare password, issue tokens.
   - Refresh: verify refresh JWT, confirm token record active/not revoked/not expired, rotate (revoke old, issue new pair) to reduce replay risk.
   - Logout: revoke presented refresh token/session.
   - `me`: return current user sans secrets.
3. Implement middleware: `authenticate` reads Bearer token, verifies signature/expiry with pinned algorithm, loads/attaches minimal `req.user` (`id`, `role`); `requireAdmin` returns 403 for non-admin. Ensure Express 5 async handlers propagate errors to centralized error middleware.
4. Implement admin password reset endpoint `POST /api/admin/users/:id/reset-password` (admin-only): validate new password, hash, update user, revoke existing refresh tokens for that user to invalidate old sessions.
5. Wire routes under `/api/auth` and `/api/admin`, add `express.json()`, helmet, cors (allow-list from env), morgan (dev), and rate limiting on login/register/refresh.
6. Add consistent error responses (JSON with message; include field errors for validation where helpful for Vuetify forms).
</action>
<verify>
- API starts and connects to DB.
- Manual/API checks: register returns 201 + tokens/user(role client); login returns tokens; refresh rotates; logout revokes; invalid/expired tokens yield 401.
- Client token cannot access admin reset endpoint (403); missing token yields 401.
- After admin reset, old refresh tokens no longer work and client can login with new password.
</verify>
<done>Auth/RBAC API satisfies AUTH-01..04 server-side behaviors with secure defaults.</done>
</task>
