# Plan 01-01: Scaffold, Infra, and Database Schema

## Objective

Create the project skeleton and irreversible data foundation for Salão Linda: working `web/` (Vue 3 + Vuetify 4, Vite) and `api/` (Express 5) projects, local MySQL 8.4 infrastructure, and Knex migrations that encode schema decisions (roles, token storage support, price snapshots, statuses, timezone convention).

## Context

- Read: `.planning/phases/01-foundation-scaffold-schema-auth/01-RESEARCH.md`
- Stack constraints: Node 26 LTS target, Express 5, MySQL 8.4 LTS, Knex 3.3 + mysql2, JS (no TS), `SALON_TZ=Africa/Maputo`, wall-clock `DATETIME` (not `TIMESTAMP`), `DECIMAL(10,2)` for money.
- Web scaffold **must** use `npm create vuetify@latest` template (avoid Vite 8 / Vuetify 4 cascade-layer issues).
- Greenfield repo; create sensible `.gitignore`, env examples, and root-level dev docs.

<task id="3" type="database">
<title>Implement Knex migrations and admin bootstrap</title>
<files>
- `api/knexfile.*` (or `knexfile.js`)
- `api/migrations/*_create_users.js`
- `api/migrations/*_create_refresh_tokens.js`
- `api/migrations/*_create_services.js`
- `api/migrations/*_create_appointments.js`
- `api/migrations/*_create_reviews.js`
- `api/seeds/*` or `api/scripts/bootstrap-admin.*` (deterministic)
</files>
<action>
1. Configure Knex for MySQL (mysql2 client), migrations directory, and environment-based connection. Ensure default DB/session behavior is compatible with `SALON_TZ`/wall-clock storage (set connection timezone or document server `TZ`; avoid `TIMESTAMP` columns for booking times).
2. Write migrations:
   - `users`: id PK, name, phone (unique), email nullable, password_hash, role enum('client','admin') default 'client', created_at/updated_at DATETIME.
   - `refresh_tokens`: id PK, user_id FK (cascade), token_hash or jti (unique/indexed), expires_at DATETIME, revoked_at DATETIME nullable, created_at DATETIME, indexes for lookup/cleanup.
   - `services`: id, name, description, price DECIMAL(10,2), duration_minutes int, image_path nullable, active boolean default true, timestamps.
   - `appointments`: id, user_id FK, service_id FK, starts_at DATETIME, ends_at DATETIME, status enum('pendente','confirmada','rejeitada','cancelada','concluida'), price_at_booking DECIMAL(10,2), duration_at_booking int, rejection_reason nullable, timestamps; indexes `(status, starts_at)`, `(user_id, starts_at)`, and a date/supporting index useful for overlap queries.
   - `reviews`: id, appointment_id FK unique, user_id FK, rating, comment, timestamps.
3. Provide `down` migrations that drop in safe dependency order.
4. Add deterministic admin bootstrap (seed or script) that creates/updates an admin account from env vars (e.g. `ADMIN_PHONE`, `ADMIN_PASSWORD`, `ADMIN_NAME`) so AUTH-02 can be exercised without manual DB hacks; document usage in README.
</action>
<verify>
- `npm run migrate:latest` succeeds on a fresh DB.
- `npm run migrate:rollback` and re-migrate succeed.
- Tables/columns/types verified via MySQL client (`DESCRIBE users/appointments/services`, confirm DECIMAL/DATETIME/ENUM).
- Admin bootstrap creates a user with `role='admin'`.
</verify>
<done>Schema is migrated, reversible, and encodes core business invariants; an admin login principal can be created deterministically.</done>
</task>
