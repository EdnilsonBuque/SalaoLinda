# Phase 1 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **This document is the design-system foundation.** Phases 2–4 inherit every token, type role, copy rule and component convention declared here. Any new UI in later phases must map to these roles — do not invent new colors, font sizes, or button styles.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none (Vuetify theme tokens — shadcn does not apply to Vue/Vuetify) |
| Preset | not applicable |
| Component library | **Vuetify 4 (core components only — no Labs components anywhere in the booking/auth flows)** |
| Icon library | **MDI** (`@mdi/font` 7.4.47, already installed) — use `mdi-*` names only, no emoji, no custom SVG icons |
| Font | **Roboto** (body/labels, `@fontsource/roboto` already installed) + **Playfair Display** (headings/display only — add `@fontsource/playfair-display` weights 600) |
| Locale | `pt` — Vuetify `locale: 'pt'` (already set in `web/src/plugins/vuetify.js`); all user-facing copy hardcoded pt-PT, **no vue-i18n** |
| Theme | Light only (`defaultTheme: 'light'`). No dark mode, no theme toggle in v1. |

**Theme file:** all tokens below are implemented in `web/src/plugins/vuetify.js` inside `themes.light.colors` / `theme.font` / `theme.variables`. The current scaffold theme (`primary: #7C3AED` violet, `secondary: #EC4899` pink, `background: #FAFAFA`) is **replaced** — violet/pink reads generic-tech, not warm salon. Because every existing view already uses `color="primary"` / `bg-background`, changing the token values restyles Login, Register, Home, App-bar and Admin-reset with **zero view edits**.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding, label-to-field micro gaps |
| sm | 8px | Between stacked form fields, button top-margin, chip padding |
| md | 16px | Default element spacing, page horizontal padding, card gutter |
| lg | 24px | Card inner padding (`pa-6`/`px-6`), section padding |
| xl | 32px | Layout gaps between cards |
| 2xl | 48px | Major section breaks, vertical rhythm on empty states |
| 3xl | 64px | Page-level spacing (top/bottom of standalone screens) |

Exceptions (non-4px values that are allowed):
- **Safe-area insets:** `env(safe-area-inset-top)` / `env(safe-area-inset-bottom)` / `env(safe-area-inset-left/right)` — native, applied as additive padding, never as a spacing token.
- **Hairlines:** 1px borders/dividers (`v-divider`, field outlines).
- **Touch targets:** interactive controls have `min-width/min-height: 48px` (Vuetify icon buttons default 40px → bump to 48px on mobile via density/size) — accessibility floor, not a spacing token.
- **Fixed component heights:** app bar 56px (`density="comfortable"`), text field ~56px — library-owned, not tokens.

## Typography

Exactly **4 type roles**, **2 UI weights** (400 regular + 500 medium) plus one display-only weight (600, Playfair only — Roboto has no 600, do not fake it):

| Role | Family | Size | Weight | Line Height | Usage |
|------|--------|------|--------|-------------|-------|
| Display | Playfair Display | 28px | 600 | 1.2 | Auth screen titles ("Entrar", "Criar conta"), brand wordmark moment |
| Heading | Playfair Display | 20px | 600 | 1.25 | Card titles, app-bar title, section titles, empty-state headings |
| Body | Roboto | 16px | 400 | 1.5 | Paragraphs, input text, list item titles, alert text |
| Label | Roboto | 14px | 500 | 1.4 | Buttons, field labels, field hints/errors, menu items, captions, chips |

Implementation in `createVuetify`:
- `theme.font.families = { heading: "'Playfair Display', serif", body: "Roboto, sans-serif", title: "'Playfair Display', serif", button: "Roboto, sans-serif" }`
- `theme.variables = { headings-font-family: "'Playfair Display', serif", font-family: "Roboto, sans-serif" }`
- Vuetify text utilities in views: `text-display` (h1 on auth screens), `text-h5`/`text-h6` must map to 28/20px via the heading family — do **not** use Vuetify's default `text-h1..h6` scale beyond these roles (its 96/60/48px sizes are desktop-display and banned at 360px).
- Load only: Playfair Display 600, Roboto 400 + 500 (subset latin + latin-ext for pt accents: á ã ç é í ó õ ú).

Rules:
- No font size below 14px anywhere. Field hints and error text = Label role (14/500).
- All weights come from the two declared sets; no italics except quoted review text (future phase).
- Currency, phone numbers and times render in Roboto (body/label), never Playfair.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#FAF7F4` warm cream | App background (`background` token), screen canvas |
| Secondary (30%) | `#FFFFFF` (cards/sheets) + `#F1E8E3` warm sand (`surface-variant`: input fills, tonal-alert backgrounds, dividers areas, skeleton blocks, menu/list hover) | Cards, menus, dialogs, form surfaces, app-bar dropdowns |
| Accent (10%) | `#A63D62` deep rose (`primary` token) | See reserved list below |
| Ink | `#2B2226` warm near-black | Primary text (`on-background`, `on-surface`) |
| Ink muted | `#6E6266` | Secondary text, hints, subtitles (`on-surface` variant) — 5.9:1 on white |
| Destructive | `#B3261E` (`error`) | Error alerts, field errors, destructive confirmation buttons only |
| Success | `#2E7D32` (`success`) | Success alerts, `confirmada`/`concluída` status semantics |
| Warning | `#FB8C00` (`warning`) | `pendente` status semantics, rate-limit warnings |
| Info | `#2196F3` (`info`) | Neutral informational notices |

Accent (`#A63D62`) is reserved for — **exhaustive list, never extend without updating this contract**:
1. Primary CTA buttons (`v-btn` filled: Entrar, Criar conta, Redefinir palavra-passe)
2. Text/link buttons ("Criar conta", "Entrar" cross-links) and inline links
3. The app bar background (56px strip — brand anchor, still ≈10% of screen)
4. Focus rings (`:focus-visible` outline 2px `#A63D62`, offset 2px)
5. Active/selected indicators (active nav icon, selected menu item, required-field asterisk)
6. Brand wordmark accents (the word "Linda" in the login header, if colored)

Accent is **never**: page backgrounds, card fills, body text, large decorative blobs, disabled states.

Contrast requirements (verified): rose on white 6.05:1 ✓; white on rose 6.05:1 ✓ (filled buttons use white text); ink on cream ≈15:1 ✓; muted ink on white 5.9:1 ✓. All body text ≥ 4.5:1.

**Status chip palette (declared here for Phase 2+ inheritance — color + icon + text label always, never color alone):**

| Status | Tonal bg / text | Icon | Text label |
|--------|-----------------|------|------------|
| pendente | warning | `mdi-clock-outline` | "Pendente" |
| confirmada | success | `mdi-check-circle-outline` | "Confirmada" |
| rejeitada | error | `mdi-close-circle-outline` | "Rejeitada" |
| cancelada | muted grey (`surface-variant` + ink muted) | `mdi-cancel` | "Cancelada" |
| concluída | primary (rose) | `mdi-star-outline` | "Concluída" |

## Component Inventory (Phase 1)

All Vuetify **core**, no Labs:

| Component | Contract |
|-----------|----------|
| `v-app` / `v-main` | Root shell; `v-main` background = `background` token; content wrapped so safe-area padding applies |
| `v-app-bar` | Shown only when authenticated; `color="primary"`, `density="comfortable"`, `flat`; padding-top includes `env(safe-area-inset-top)`; title "Salão Linda" in Heading role, white; actions: `mdi-home` icon button, admin-only `mdi-account-key` icon button (48px target), account `v-menu` via `mdi-account-circle` |
| Account `v-menu` | White surface, `v-list`: row 1 = user name (Body 400) + subtitle "Admin (Dona)"/"Cliente" (Label, muted); `v-divider`; row "Sair" with `mdi-logout`. Menu closes before navigation. |
| `v-card` | `rounded="lg"` (12px), white surface, elevation 2 max, padding 24px (`lg`) on auth cards, 16–24px elsewhere; auth card `max-width: 440px`, centered |
| `v-btn` | Filled primary = primary CTA (block, `size="large"`, min-height 48px, Label 14/500 white, uppercase **off** — sentence case); Text variant = cross-links (rose); Icon variant in app bar (white, 48px target); `:loading` while submitting, disabled during load |
| `v-text-field` | Default outlined variant; label in Label role; leading icon `mdi-*`; **password fields add `append-inner-icon` eye/eye-off reveal toggle**; `type="tel"` + `inputmode="tel"` for contact; inline `error-messages` below field (Label, error color, with `mdi-alert-circle-outline` icon prefix — error never color-only) |
| `v-select` | Admin reset client picker only; shows `Nome (contacto)`; persistent hint below |
| `v-alert` | `variant="tonal"` only (error/success/info); sits above the form inside the card; max 2 lines; carries icon + text |
| `v-form` | `@submit.prevent`; Enter submits; first invalid field receives focus on failed validation |
| `v-menu` / `v-list` / `v-list-item` / `v-divider` | Account menu as above |
| `v-progress-circular` | Session-restore splash: centered, primary color, indeterminate — shown while `auth.hydrate()` runs, **before** any layout renders (no app-bar flash) |
| `v-skeleton-loader` (optional) | Admin reset user-list loading state |

**Layout patterns:**
- **Auth screens (Login/Registo):** full-height centered card, horizontal page padding 16px, card max-width 440px; stack = Display title → Heading subtitle "Salão Linda" → optional tonal alert → fields (8px rhythm) → primary CTA (8px top) → cross-link footer (16px top). One screen only for registo — **no role selector ever appears in the UI** (role is forced `client` server-side).
- **Authenticated shell:** app bar + `v-main` content with 16px padding; every screen reachable in one tap from app bar/menu.
- **Admin area (placeholder):** route `/admin/utilizadores`, guarded `meta.admin`; content = card "Redefinir palavra-passe de cliente" + explanatory subtitle; admin also gets the info alert on Home pointing to the menu.

## Interaction & States Contract

| State | Contract |
|-------|----------|
| Initial load | Centered `v-progress-circular` on cream background until `auth.hydrate()` resolves; no skeleton flash of app bar |
| Submit loading | CTA button `:loading` + `disabled`; form fields disabled; double-submit impossible |
| Field error | Server `fieldErrors` → inline `error-messages` under the offending field; focus moves to first invalid field |
| Form error | Server `message` → tonal error `v-alert` above form (never toast-only for auth failures) |
| Success | Tonal success `v-alert` (admin reset); auth success navigates immediately (no success screen) |
| Offline / network error | "Sem ligação ao servidor. Tenta novamente." in the form-level error alert; CTA re-enabled for retry |
| Empty list (admin user picker) | Inline: "Nenhum cliente registado ainda." (Label, muted) |
| Focus visible | 2px rose outline, 2px offset, on every interactive element (`:focus-visible`) |
| Disabled | Muted, `cursor: not-allowed`, ink-muted text — never rose |
| Transitions | None beyond Vuetify defaults — no page fade/slide animations in v1 |

**Keyboard & safe area (Capacitor WebView — from day 1, not Phase 4):**
- `web/index.html`: add `viewport-fit=cover` to the viewport meta; set `lang="pt"`; title → `Salão Linda`.
- App bar: `padding-top: env(safe-area-inset-top)`; screens/bottom bars: `padding-bottom: env(safe-area-inset-bottom)`.
- Auth forms must remain scrollable (`overflow-y: auto` on the fill-height container) so the **lowest input + CTA stays above the soft keyboard** on a 360×640 device.
- Hardware back button (register once at bootstrap): close open overlay (dialog/menu/sheet) first → `router.back()` → only at root `App.minimizeApp()`. A dialog must never close *and* navigate on one press.
- Status bar: CSS-first safe-area padding only — no `StatusBar.setOverlaysWebView` reliance (no-op on Android 15+).

All copy hardcoded pt-PT (formal "tu"/"você"-neutral — match existing: "Não tem conta?", "Já tem conta?").

| Element | Copy |
|---------|------|
| Primary CTA — Login | **Entrar** |
| Primary CTA — Registo | **Criar conta** (change current button text "Registar" → "Criar conta") |
| Primary CTA — Admin reset | **Redefinir palavra-passe** |
| Cross-link — Login footer | "Não tem conta?" + link **Criar conta** |
| Cross-link — Registo footer | "Já tem conta?" + link **Entrar** |
| Field labels | "Nome", "Contacto (telefone)", "Palavra-passe", "Confirmar palavra-passe", "Nova palavra-passe", "Cliente" |

| Error state — register (generic) | "Não foi possível criar a conta. Tenta novamente." |
| Error state — network | "Sem ligação ao servidor. Tenta novamente." |
| Error state — 403 (client hits admin route) | "Não tens permissão para esta área." + redirect home (server 401/403 is the real boundary; UI text is courtesy only) |
| Empty state heading — Home (cliente) | "Bem-vinda/o, {nome}" |
| Empty state body — Home | "Os serviços e as marcações chegam nas próximas fases. Por agora podes gerir a tua conta." + next step: nothing to click (info only) |
| Empty state heading — Admin home notice | "Área de gestão" |
| Empty state body — Admin home notice | "As ferramentas do salão chegam nas próximas fases. Usa o menu para redefinir palavras-passe de clientes." + next step: link to `/admin/utilizadores` |
| Empty state — admin picker | "Nenhum cliente registado ainda." |
| Success — admin reset | "Palavra-passe redefinida. O cliente já pode entrar com a nova palavra-passe." |
| Destructive confirmation — admin reset | Dialog title: **Redefinir palavra-passe?** Body: "A palavra-passe de {nome} vai ser alterada. A partir de agora terá de usar a nova palavra-passe para entrar." Buttons: "Cancelar" (text) / **Redefinir** (filled, error color) |
| Logout (no confirmation) | Menu item **Sair** → immediate logout → redirect `/login`. Fast path, no dialog (default: logout is not destructive). |
| Forced logout (expired session) | Navigate to `/login`; if a message is shown: "A tua sessão terminou. Entra outra vez." |

Destructive actions in Phase 1: **only** the admin password reset (confirmation dialog above). Logout is exempt.

## Inheritance Rules for Phases 2–4

1. **Colors:** every new surface/text/accent must map to a role in the Color table. New semantic colors require an update to this file first.
2. **Type:** only the 4 roles. Status chips, prices (`1 200,00 MZN` format), durations ("45 min") and times (`HH:mm`) use Label/Body roles in Roboto.
3. **Spacing:** 4px scale only; mobile-first at 360px is the layout baseline (breakpoint `sm` and up is a bonus, never the design target).
4. **Components:** core Vuetify only. Labs (`VTimeInput`, etc.) are banned in booking flows (STACK §4.5). Mobile lists (Minhas Marcações, admin tables) use card/list layouts, **not** `v-data-table`, at 360px (PITFALLS: horizontal-scroll trap).
5. **Copy:** pt-PT hardcoded; sentence case buttons; status labels exactly "Pendente/Confirmada/Rejeitada/Cancelada/Concluída".
6. **Mobile:** safe-area padding and the hardware-back overlay rule apply to every new overlay/dialog/sheet.
7. **Accessibility:** touch targets ≥48px, focus-visible rose ring, errors = icon + text (never color alone), contrast ≥4.5:1.
