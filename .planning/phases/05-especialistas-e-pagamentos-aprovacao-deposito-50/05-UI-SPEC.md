# Phase 5 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Inheritance:** every token, type role, color role, copy rule and component convention from `01-UI-SPEC.md` (design-system foundation) and `02-UI-SPEC.md` (booking/estado patterns) stays in force. This document only declares what Phase 5 **adds or extends** — no new colors, font sizes or button styles are introduced except the two new status chips explicitly declared below.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none (Vuetify theme tokens — shadcn does not apply to Vue/Vuetify; `components.json` absent) |
| Preset | not applicable |
| Component library | **Vuetify 4 (core components only — no Labs anywhere)** |
| Icon library | **MDI** (`@mdi/font`) — `mdi-*` names only, no emoji, no custom SVG |
| Font | **Roboto** (body/label) + **Playfair Display 600** (headings) — unchanged from Phase 1 |
| Locale | `pt` Vuetify locale; all copy hardcoded pt-PT, no vue-i18n |

**Live theme note (current code):** `web/src/plugins/vuetify.js` currently ships `primary: #624650`, `secondary: #9A8061`, `background: #F7F4EF`. These are the tokens in force (Phase 1 spec's rose values were superseded by the implemented theme). Phase 5 must **reuse** these tokens via `color="primary"` / theme roles — never hardcode hex in views. Status-chip semantics (`appointmentStatus()` in `web/src/services/formatters.js`) remain the single source for label/color/icon.

## Spacing Scale

Inherited unchanged from Phase 1 (multiples of 4): **4 / 8 / 16 / 24 / 32 / 48 / 64 px**.

| Token | Value | Phase 5 usage |
|-------|-------|---------------|
| xs | 4px | Chip icon-to-text gap, inline price separators |
| sm | 8px | Stacked buttons in approve/reject row, PIN field spacing |
| md | 16px | Page padding, card gutter, payment sheet padding |
| lg | 24px | Card inner padding (appointment + payment cards) |
| xl | 32px | Gap between payment stepper steps |
| 2xl | 48px | Payment screen section breaks |
| 3xl | 64px | Payment confirmation screen top/bottom rhythm |

Exceptions (non-4px, allowed — same list as Phase 1):
- Safe-area insets `env(safe-area-inset-*)` (bottom nav + payment sheet bottom padding).
- 1px hairlines/dividers.
- **Touch targets ≥48px** — applies with special force to the payment PIN input (min-height 48px) and slot/specialist action buttons.
- Fixed heights: app bar 56px, `v-bottom-navigation` 56px, text fields ~56px.

## Typography

Unchanged — exactly 4 roles, 2 UI weights (400 + 500) + Playfair-only 600:

| Role | Family | Size | Weight | Line Height | Phase 5 usage |
|------|--------|------|--------|-------------|---------------|
| Display | Playfair Display | 28px | 600 | 1.2 | Payment amount headline ("Depósito de 50%"), payment success heading |
| Heading | Playfair Display | 20px | 600 | 1.25 | Card titles, inbox title "Aprovações", sheet/dialog titles |
| Body | Roboto | 16px | 400 | 1.5 | Card body, deadline sentences, payment descriptions, PIN input text |
| Label | Roboto | 14px | 500 | 1.4 | Buttons, chips, field labels, hints/errors, countdown text, breakdown rows |

Rules reaffirmed: no size <14px; currency (`1 200,00 MZN`), times (`HH:mm`) and dates (`DD [de] MMMM`) in Roboto only; sentence-case buttons; never fake Roboto 600.

## Phase 5 Surfaces — Layout & Interaction Contract

### 1. Specialist bottom navigation (role `especialista`)

- `web/src/App.vue` `v-bottom-navigation` gains a third branch (after cliente, admin): **especialista sees exactly 3 tabs**:

| Tab | Route | Icon | Label |
|-----|-------|------|-------|
| Início | `/` (HomeView, specialist variant) | `mdi-home` | "Início" |
| Aprovações | `/especialista/marcacoes` | `mdi-checkbox-marked-circle-outline` | "Aprovações" |
| Mais | opens `v-bottom-sheet` | `mdi-dots-horizontal` | "Mais" |

- "Mais" sheet (same pattern as admin): rows "Conta" (name + subtitle "Especialista", from account menu logic) and **"Sair"** (`mdi-logout`, immediate logout, no dialog — Phase 1 rule).
- Existing cliente/admin branches untouched. `auth` store gains `isEspecialista` getter (`user.role === 'especialista'`); router gains `meta.especialista` guard — server 403 remains the real boundary.
- Login screen: no UI change (no role selector ever). The account menu subtitle reads **"Especialista"** instead of "Cliente"/"Admin (Dona)".

### 2. Caixa de aprovação do especialista (`/especialista/marcacoes`)

- **Layout:** vertical scroll list of `v-card` (rounded, white, elevation ≤2) — same list pattern as `AppointmentsView` / `AdminAppointmentsView`. App bar title **"Aprovações"**. Default filter: `pendente` (segmented `v-btn-toggle`: "Pendentes" / "Todas").
- **Each card:**
  - Date `DD [de] MMMM` + time `HH:mm – HH:mm` (Body 14, muted).
  - Service name (Heading 20 Playfair) + client name/contact (Body 16).
  - Status chip (per extended palette above).
  - Row of actions **only when `pendente`**:
    - **"Aprovar"** — filled `primary`, min-height 48px, `prepend-icon="mdi-check"`.
    - **"Rejeitar"** — outlined `error`, min-height 48px, `prepend-icon="mdi-close"`.
  - `:loading` on the pressed button while PATCH is in flight; other action disabled during load (no double-submit).
- **Reject dialog** (`v-dialog`, white surface, Heading title): title **"Rejeitar marcação?"**; body "A cliente recebe o motivo. Escreve um motivo curto (opcional)."; `v-text-field` label "Motivo (opcional)", max 50 chars, counter; buttons "Cancelar" (text) / **"Rejeitar"** (filled `error`).
- **Success feedback:** tonal `v-alert` at top of list — success: "Marcação aprovada. A cliente tem {prazo} para pagar o depósito." / success: "Marcação rejeitada." (auto-dismiss 4 s).
- **Empty state:** centered `mdi-checkbox-marked-circle-outline` 48px primary icon + Heading **"Sem marcações por aprovar"** + Body "As marcações dos teus serviços aparecem aqui assim que uma cliente marcar." — no CTA.
- **Error state:** tonal error alert "Não foi possível atualizar a marcação. Tenta outra vez." + list stays rendered.
- **Visibility contract (SPEC-02):** list renders ONLY `appointment.specialistId === current specialist` — the other specialist's rows never reach the DOM; admin's total view lives in the existing `/admin/marcacoes`.

### 3. Payment flow — depósito de 50% (client)

Entry: `aguarda_deposito` card in **Minhas Marcações** (`/marcacoes`) shows a full-width primary button **"Pagar depósito"** (`mdi-cash`) + a Label-role line: **"Depósito de {X} MZN até {DD [de] MMMM, HH:mm}."** When deadline <2 h, that line renders in `warning` color with `mdi-alert-circle-outline` prefix.

Route `/marcar/:serviceId/pagamento` (or `/pagamentos/:appointmentId`) — single scrollable screen:

1. **Resumo card:** service name (Heading), date/time (Body), specialist name chip ("Com {nome}" — `variant="tonal"`, `primary`), breakdown rows (Label, right-aligned values): "Total do serviço: X MZN" / **"Depósito (50%): X MZN"** / "Restante no salão: X MZN". Divider, then deadline sentence from above.
2. **CTA:** block primary filled **"Pagar depósito"**, min-height 48px, `:loading` during gateway call, disabled once pressed until callback resolves.
3. **Payment prompt (sandbox mobile-money semantics, PAY-04)** — rendered as an in-app `v-bottom-sheet` (white, `rounded="xl"` top, safe-area bottom padding), 3 steps inside the sheet via `v-window` (core):
   - **Step 1 — Descrição:** heading "Pedido de pagamento", body "{Salão Linda} pede-lhe pagar **{X} MZN** — Depósito marcação {serviço}.", merchant row (avatar `mdi-store`), buttons: "Cancelar" (text) / "Continuar" (primary).
   - **Step 2 — PIN:** `v-text-field` label **"PIN M-Pesa"**, `type="password"`, `inputmode="numeric"`, maxlength 4, leading `mdi-lock-outline`, min-height 48px; wrong-PIN inline error (Label, error, icon): "PIN incorreto. Tenta outra vez."; button **"Confirmar pagamento"** (primary, block, `:loading`).
   - **Step 3 — Confirmação:** success → sheet closes, screen shows success block: Display heading **"Pagamento confirmado"** + `mdi-check-circle` success icon + Body "A tua marcação está confirmada. Vemos-te no salão!" + primary button **"Ver marcações"** → `/marcacoes` (chip now `confirmada`). Failure → tonal error alert inside sheet: **"Pagamento não concluído. Nenhuma cobrança foi feita — tenta outra vez."** + "Tentar outra vez" (primary) / "Cancelar" (text). Pending callback → centered `v-progress-circular` + "A aguardar confirmação do operador…" (Info semantics).
   - Sheet can only be dismissed by Cancelar or success — never by outside-tap while PIN is being processed (prevents half-state).
4. **Error states (screen-level):**
   - Network: "Sem ligação ao servidor. Tenta novamente." (Phase 1 string, reused).
   - Expired during flow: tonal warning alert **"O prazo do depósito terminou. O horário foi libertado — escolhe outra data."** + button "Escolher serviço" → `/servicos`.
   - Already paid: redirect to `/marcacoes` (no dead-end payment screen).

### 4. New states in Minhas Marcações (client)

- `aguarda_deposito` card: chip "Aguarda depósito" (info) + deposit line + **"Pagar depósito"** primary CTA + cancel action **kept** (cancel during deposit wait = `cancelada`, no refund automation — v1 manual).
- `expirada` card: chip "Expirada" (muted) + Body line **"O depósito não foi pago a tempo e o horário foi libertado."** + text/primary button **"Marcar outra vez"** → `/servicos`. Non-destructive, no confirm dialog.
- `confirmada` card additionally shows success badge "Depósito pago".
- `concluida` card shows payment breakdown badges: "Depósito pago" + ("Restante pago" | "Restante por pagar") + Label line "Total: X MZN".
- Card order, date/time formats, cancel button and review block: unchanged from Phase 2/3 contracts.

### 5. Admin agenda (`/admin/marcacoes`) extensions

- Filter `v-select`/chips gain the two new statuses ("Aguarda depósito", "Expirada") alongside existing options.
- Rows with `aguarda_deposito` show the info chip + Label line "Depósito até {data}" (admin read-only — no admin pay button on behalf of client).
- `concluida` rows gain:
  - Payment badge row: "Depósito pago" (success) + "Restante por pagar" (warning) or "Restante pago" (success).
  - **Action button when remaining due:** outlined primary **"Marcar restante pago"** (`mdi-cash-check`), min-height 48px → confirmation `v-dialog`: title **"Registar pagamento do restante?"**; body "Vai registar {X} MZN recebidos no salão para {serviço} de {cliente}. Fica no histórico da marcação."; buttons "Cancelar" (text) / **"Registar"** (filled primary). Success → tonal success alert "Restante registado." + badges flip to "Restante pago".
- Specialist visibility (SPEC-03): every row shows a small "Com {nome}" chip (`variant="tonal"`, primary) so the admin sees routing at a glance. Existing confirm/reject admin actions remain for visibility but approval authority belongs to the specialist (ADM-01 annotated) — admin approve/reject buttons are hidden for `pendente` rows; admin sees read-only chip + "A aguarda do especialista" hint (Label, muted).

### 6. Admin service form — campo de especialista (SPEC-01)

- `AdminServicesView` create/edit dialog gains one field after "Duração":
  - `v-select`, label **"Especialista"**, required, items: **"Cabeleireiro"** / **"Manicurista/Pedicurista"** (hardcoded pt-PT bootstrap pair), leading icon `mdi-account-tie`, persistent hint: "As marcações deste serviço vão para este especialista."
  - Missing selection → inline error "Escolhe o especialista deste serviço." (Label, error, icon prefix).
- **Service cards (client `ServicesView` + admin list):** under price/duration row, add a tonal chip `primary`: **"Com {nome}"** (`mdi-account-tie` start icon, Label 14). Placeholder when unset (legacy rows): muted chip "Sem especialista" — admin-only rendering; client cards for services without specialist keep current layout (server should always have one post-migration).
- **Booking flow:** unchanged UI — the service implies the specialist. After submit, confirmation text (Phase 2 BOOK-03) is extended: **"Pedido enviado — à espera da aprovação de {nome}."**

## Interaction & States Contract (Phase 5 additions)

| State | Contract |
|-------|----------|
| Initial load | Existing `v-progress-circular` splash; inbox/payment lists show `v-skeleton-loader` (3 card placeholders, sand `surface-variant`) until fetch resolves |
| Action loading | Only the pressed button gets `:loading` + sibling disabled; PIN sheet blocks double-tap during callback |
| Field error | Inline `error-messages` under field (Label + error + icon) — PIN, motivo, especialista field |
| Form/server error | Tonal `v-alert` above the form/card content — never toast-only |
| Success | Tonal success `v-alert` or dedicated success block (payment step 3); auto-dismiss 4 s for list feedback |
| Offline/network | "Sem ligação ao servidor. Tenta novamente." — CTA re-enabled for retry |
| Empty list | Centered icon (48px, primary) + Heading + Body (copy below) |
| Deadline urgency | <2 h → warning-colored countdown text with icon; ≥2 h → muted ink; never color-only |
| Focus visible | 2px `primary` outline, 2px offset, all interactive elements |
| Disabled | Muted, `cursor: not-allowed`, ink-muted — never primary |
| Overlays | Every dialog/sheet follows hardware-back rule: first back press closes overlay only (Phase 1) |
| Transitions | Vuetify defaults only — no custom page animations |
