# Plan 02-01: Services & Booking Core

## Objective

Deliver the product core: service CRUD (admin + client catalog), availability/slot engine with no double-booking, booking flow with pending state, Minhas Marcações with cancel, and admin confirm/reject inbox — all race-safe from day one.

## Context

- Depends on Plan 01-01 (scaffold, env, DB, migrations, admin bootstrap) and 01-02 (auth JWT/RBAC + session persistence).
- Read: `.planning/phases/02-services-booking-core/02-RESEARCH.md`
- Requirements mapping: SERV-01..04 (admin CRUD client view), BOOK-01..04 (booking flow + availability), APPT-01..03 (Minhas Marcações + cancel), ADM-01 (confirm/reject inbox).
- Security baseline: bcryptjs cost 12, JWT verify with pinned algorithm (HS256), role hardcoded/validated server-side, never trust client role.
- STACK decisions: dayjs + DATETIME wall-clock (Africa/Maputo), Vuetify 4 core components, `GET_LOCK` per day + `SELECT ... FOR UPDATE` overlap check.

<task id="2" type="backend-booking">
<title>Implement booking engine with transactional overlap guard</title>
<files>
- `api/src/services/availability.service.*` (slot generation + overlap check)
- `api/src/middleware/validateSlot.*` (or inline in route)
- `api/src/routes/appointments.routes.*`
- `api/src/middleware/requireAdmin.*` (reuse)
</files>
<action>
1. Implement availability service:
   - `generateSlots(date, serviceDuration, openingHours)` → greedy walk over opening hours in `duration_minutes` steps, filtering out intervals that overlap existing `pending`+`confirmed` appointments (already booked slots).
   - `checkOverlap(date, start, end, serviceDuration)` → SQL overlap predicate inside transaction: `WHERE starts_at < :newEnd AND ends_at > :newStart AND status IN ('pendente','confirmada')`; returns rows if conflict.
2. Booking flow:
   - `POST /api/appointments` → receives `{serviceId, date, startTime}` → calls `generateSlots` to power picker UI (already free slots) → then calls `checkOverlap` in a transaction with `SELECT ... FOR UPDATE` / `GET_LOCK` → if 0 rows → INSERT appointment status='pending', `price_at_booking` snapshot, `duration_at_booking` → response `{id, status: 'pending'}` → slot immediately disappears for other clients (pending blocks availability).
   - Return 409 with conflict message if overlap detected.
3. Middleware: ensure JWT `req.user` attached; admin-only routes for confirm/reject use `requireAdmin`.
</action>
<verify>
- Two simultaneous `POST /api/appointments` for the same free slot → one returns 201 + pending, the other returns 409 "horário acabou de ser ocupado"; availability updated.
- `generateSlots` for a 60-min service over 09:00–18:00 returns exactly the free 15-min slots; no overlap with existing bookings.
- Appointment created with status='pending', `price_at_booking` = service.price at write time.
</verify>
<done>Booking engine with transactional guard satisfies BOOK-01..04 and APPT-01..03 server-side.</done>
</task>
